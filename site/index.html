The terminal, rewired.

glyphwire replaces the stream of escape codes with a real protocol. Programs draw layers, tables, images, splits and panes over a local socket, and the display keeps them alive and interactive. Every ordinary terminal program still just works.

Why not just a terminal emulator?

A terminal emulator gives a program one thing: a byte stream it can sprinkle escape codes into. Everything richer is a hack layered on top, and it all disappears the moment the program exits. glyphwire starts from the other end.

Objects, not paint

In a terminal emulator, a program paints characters and forgets them.

In glyphwire, tables, outlines, layers and panes are server-side state. A gw-ls -l table stays sortable by clicking a header long after gw-ls has exited.

Real images

In a terminal emulator, images are base64 stuffed into escape codes, in whichever of several competing formats it supports.

In glyphwire, PNG, JPEG, BMP and GIF bitmaps are placed in the grid, their bytes on a binary side channel. Nine-patch panels and an icon catalog too.

No flicker, no tearing

In a terminal emulator, a big redraw arrives and paints a band at a time.

In glyphwire, a batch applies many messages under one lock and shows them as one frame. Scrolling and highlights move on the host without a repaint.

Structured input

In a terminal emulator, a program parses mouse and key escape sequences and guesses at modifiers.

In glyphwire, a program subscribes to key, text, mouse, scroll and resize events with full modifier state, key up and down, and its own key repeat.

Layout the host owns

In a terminal emulator, tmux re-encodes every pane through a single stream.

In glyphwire, splits, panes and dividers live in the host. gmux is a multiplexer that never draws a cell or touches a program's I/O.

Themes as meaning

In a terminal emulator, there are 16 colours and every app hard-codes its own RGB.

In glyphwire, programs paint roles like keyword or table_header_bg, so switching theme recolours everything already on screen, live.

And it's still a terminal: plain programs run on a PTY with their escape sequences interpreted. vim, htop and your build scripts run unchanged, and a glyphwire program run outside a session falls back to plain stdout.

What the display can do

One host, one protocol. Any program in any language can use all of it.

Contexts

Independent full-window surfaces: a generalized alt-screen. Your shell's scrollback waits untouched under a full-screen app. Super+F12 switches between them.

Panes & splits

A window-level split tree of panes on host-managed PTYs, plus layer splits inside each, with draggable dividers that keep their ratios.

Layers

Positioned surfaces with opacity, backgrounds, drop shadows and host-side scrolling over content larger than the view, with real scrollbars.

Rich text

Truecolor styled spans, headings at 1.5×, 2× and 3× from re-rasterized fonts, colour emoji, and multi-script text with CJK fallback.

Tables & outlines

Typed, sortable tables and collapsible trees that the host expands, collapses and re-sorts with nothing running.

Drag and drop

Alt+drag a file out of the grid into any Wayland app, even from scrollback, and accept drops onto host-highlighted targets.

Metadata

Attach opaque JSON to cells (a path to open, a link to follow) that the host stores and returns on a click.

Selection & clipboard

Host-drawn selection per layer, multi-select highlights by id, mirrored to the OS clipboard.

Remote sessions

glyphwire --ssh host carries every remote client over one ssh trunk. Remote editors and image viewers draw exactly like local ones.

A suite of apps built on it

Each is an ordinary client of the public protocol, with no private hooks into the host, and each shows off something a byte stream can't do. The guides walk through using each one.

zoe editor

A modal editor with vim's grammar and VS Code's keys side by side. Split editor groups, multi-folder workspaces, tree-sitter highlighting and language servers (diagnostics, hover, goto definition, completion as you type).

  • VS Code style find and replace, plus :s over ranges
  • Folding, auto-indent, auto-closing pairs
  • Unsaved changes backed up continuously: :q and pick up later
  • Lua extensions and fully rebindable keys

The zoe guide →

salacommander file manager

A two-pane file manager in the Norton Commander tradition, with icons, tabs, host scrollbars and modal dialogs on their own layers.

  • Drag between panes, or Alt+drag out into other apps
  • Sudo operations behind a masked password dialog
  • Desktop trash, permission and owner editing
  • Fuzzy search and a drop-down shell panel

gw-grep search

ripgrep results as a syntax-highlighted, collapsible outline right in your scrollback. The outline is server-side state, so clicking ▸ still expands a hit after the command has exited.

gw-ls listing

An ls with file-type icons, or a long listing in a real table: colour-coded sizes, striped rows, and headers you can click to re-sort whenever you like.

gwmd markdown

Markdown with scaled headings, GFM tables as native tables, inline images and links you can Tab through. Here in the Catppuccin Latte theme, one of nineteen.

gw-read comics & manga

gw-shell

The default shell: pipelines, Lua config, fish-style autosuggestions and completions, a powerline prompt, and Ctrl+R history in a real UI.

gmux

A multiplexer that is a pure window manager. It asks the host for panes and places them; it never draws or relays a byte.

The far end of an ssh session. It multiplexes remote clients onto one trunk without parsing the protocol.

A protocol you can implement in an afternoon

The display listens on a Unix socket named by GLYPHWIRE_SOCK. Messages are JSON-RPC 2.0 under Content-Length headers (the same framing as LSP), or length-prefixed MessagePack. No client library, no handshake: connect and draw.

  • A normative spec, licensed CC-BY-4.0: write a client or a host in any language
  • Integer handles for contexts, layers, tables and panes
  • Opt-in event streams, subscribed to by name
  • Unknown params ignored, so newer clients degrade gracefully

Protocol version 0.14.1, pre-1.0. The spec lists its open gap (capability negotiation) in plain sight.

Get it running

Ubuntu / Debian

Grab the .deb from the latest release.

sudo apt install ./glyphwire_<version>-1_amd64.deb

Arch Linux

Grab the .pkg.tar.zst from the latest release.

sudo pacman -U glyphwire-<version>-1-x86_64.pkg.tar.zst

From source

Needs Zig 0.17.0 and nothing else: SDL3 builds from source.

git clone https://github.com/srjilarious/glyphwire
cd glyphwire && zig build glyphwire

Release binaries need glibc 2.39 or newer (Ubuntu 24.04, Debian 13, current Arch) and a working OpenGL setup.

Open source, built to be remixed

glyphwire is one person's take on what a terminal could be. It follows a remix model: take it, fork it, bend it into your own thing. You don't need permission, and you don't need to send it back.

Bug reports, ideas and feature requests are very welcome as GitHub issues. Pull requests are by invitation, so start with an issue.
